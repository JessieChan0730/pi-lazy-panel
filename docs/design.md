## 问题描述

目前 pi 启动的 resume 感觉操作很别扭，方向键控制上下移动，然后 ctrl + d 删， 能否帮我做一个插件 lazygit 那种（hjkl, d 是删除，r 是 rename）。操作 pi resume 的插件啊？

## 项目描述

一个类似 lazygit 的插件，用来管理 pi 的历史对话，主要命令有三个 /resume（恢复会话，从历史会话中选择并恢复）  /tree  （会话树导航，跳转到对话树的任意节点继续对话，某个对话详情里面的某一个界面） /new （新建一个对话），然后还有围绕着对话进行操作的命令：/name（命名会话，为当前会话设置一个易读的名称） /session（会话信息，显示会话文件路径、ID、消息数、token 用量和费用） /fork（分叉会话，从之前的用户消息分叉出一个新会话文件）/clone（克隆会话复制当前活动分支到新会话文件）/copy （复制 AI 最后一条回复到剪贴板）/export（导出会话导出为 HTML 或 JSONL 文件）/import（导入会话从 JSONL 文件导入并恢复会话）
/share（分享会话上传为私有 GitHub Gist，生成可分享的 HTML 链接）， 根据这些命令能够拿到信息，我觉得产品可以设计成为这样：

- 左边第一个面板是显示历史对话, 也就是 /resume 里面的那些数据
- 左边第二个面板（在第一个面板底部）是显示对话节点 也就是 /tree 里面的那些数据（根据上面选择的不同的 /resume 来确自动变化这里面的内容）
- 右边第一个面板是显示对话的详细内容（需要区分是AI的消息，还是我的消息），这个面板占据全部高度
- 搜索，放在底部不需要一个输入框。当用户输入 / 时候，底部出现 搜索：两个字样，随后用户输入内容回车进行搜索（只搜索当前focus面板中的内容），这个完全参考 lazygit 就行

聚焦到得不同的面板，不同的快捷键有不同的含义。

```txt
关系其实是：
    resume1
        - tree1
            - node1
            - node2
```

也就是随着第一个面板，用户选择聚焦不同的resume,下面的第二个面板的tree也要不停变化显示不同的可还原的节点

暂定的指定（后续可能会适配）：
/compact，/settings，/changelog

确定不会用到的指令：
/login，/logout，/model，/thinking，/scoped-models

三个选项只在一点上不同：跳到目标节点后，"被放弃的那段分支"（从当前叶子往上到它和目标节点的公共祖先之间的所有消息）怎么处理。跳转本身都一样：pi 把叶子指针移到目标节点，之后发给模型的上下文变成"根 → 目标节点"这条路径；被放弃的消息仍留在会话文件里，树里还能看到、以后还能跳回去。

- No summary：只移动叶子指针，不调模型、不花钱、瞬间完成，被放弃分支上发生过的事模型完全"忘记"。适合那段分支是死胡同，或只是想回到某句话重新问。
- Summarize：pi 把被放弃分支上的消息按时间顺序序列化成文本，用当前模型写一段结构化摘要（固定格式 Goal / Constraints & Preferences / Progress（Done、In Progress、Blocked）/ Key Decisions / Next Steps，要求保留精确的文件路径、函数名和报错信息），开头加一句"用户之前探索过另一条分支，以下是那次探索的总结"，结尾附上那段分支读过和改过的文件列表。结果作为一条 `branch_summary` 条目挂在目标节点下面成为新叶子，模型继续对话时知道另一条路试过什么、有什么结论。代价是一次模型调用（输出最多 4096 token，用量计入会话总费用），要等几秒到几十秒，且必须有模型可用，否则报 `No model available for summarization`。适合那段分支做过有价值的探索或修改，想保留结论但不想把整段对话的 token 都带回来。
- Summarize with custom prompt：和 Summarize 一样，只是把输入的指令追加到默认提示词后面作为 `Additional focus: …`，默认结构仍然保留。用来指定摘要侧重点，比如"只记录和 API 改动相关的决定"或"完整保留报错堆栈"。
- 补充：目标是用户消息时，pi 把叶子移到它的父节点并把那句话填回输入框让你改了重发（摘要挂在父节点位置）；目标在当前叶子的下游（没有任何消息被放弃）时，选 Summarize 也不会调模型，等同 No summary；分支太长放不进上下文时按 `branchSummary.reserveTokens`（默认 16384）预留空间、裁掉更早的消息再总结。摘要条目在 TREE 里显示为 `system: branch summary: …`，默认过滤下隐藏，按 `a` 可见。

## 注意点

1. 搜索可以强化一下语义，可以类似于github那样：auther:xxxx 这个代表找到作者是 xxxx 的仓库，这里的顶部搜索也可以参考这种设计，例如：model:xxx 当然这个根据实际情况考虑，如果做不到就算了（我建议第一版不要做真正的 semantic search。但是可以先设计成：
/name:FilmRecall
/model:opus
/path:FilmRecall
/tag:scan
/after:2026-09-01
/before:2026-09-20）
2. 快捷键可配置，最好能够叫用户自定义快捷键，上面不是最优解, 可以通过配置文件或者在tui修改的形式来修改快捷键，并且要允许组合建，比如用户希望使用`ctrl + d` 来删除对话，这个也是可以的
3. 每次fork和delete操作的时候都需要，弹出一个对话框让用户来手动确定。（上下结构，确认和取消（y/n））
4. 右侧聊天内容要想办法区分“我”的内容和“AI”发送的内容，并且使用 markdown 渲染，最好直接用 直接用pi原生的渲染器
5. 确定左侧 resume 面板里面展示的内容，比如聊天的时间，模型，名称，运行路径，聊天内容的简介？等等不一定要全部展示，主要还是要UI美观，tree 面板就非常简单了，就按照

```txt
  user: hi
› [我的] 22:18 assistant: Hi! 👋 I'm ready to help with your **FilmRecall** Android project — whether that's writing or refactoring code, de
```

前面 `user` 代表是用户 `assistant` 代表是AI，`：`后面是内容, `[]` 里面是标签, `22:18` 是时间。
